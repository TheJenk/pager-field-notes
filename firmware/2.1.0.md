# What changed in firmware 2.1.0

Compared with 2.0.0, from the official image and testing on a Pager after updating (November
2026). "Verified" means it was reproduced on a real Pager. Hak5's own release notes ship on the
device at `/etc/changelog`; this page covers what matters when you build payloads and themes.

## At a glance
- Same base: OpenWrt 24.10.1, kernel 6.6.86. **Theme framework is still 0.9**, so themes made
  for 2.0 run unchanged.
- **Payloads are stopped as a process group** now. `setsid` workers still survive.
- **`/mmc/bin` is on the payload `PATH`.**
- **The root filesystem lives on the eMMC.**
- **SSH is dropbear** instead of OpenSSH.
- **The buzzer is a sound card**, and `pwmplay` plays mp3 files.
- New commands: `PINEAPPLE_KICK_CLIENT`, `PINEAPPLE_PINEAPD_STOP` and `_RESPAWN`. Several
  existing commands were fixed, along with a number of security issues (including an SSID
  injection in `PINEAP_SSID_MATCH` callbacks).
- Faster: about 76 s to boot-complete in one test, versus about 93 s on 2.0. Display frames are
  about 28 % quicker.

## Updating
- **Verified:** the update kept installed user payloads, themes, loot and the SSH host key (no
  host-key warning, unlike 2.0). It **reset the active theme to the stock one**, and it **dropped
  files added outside `/mmc`** and the saved settings, such as links you made in `/usr/bin`.
- If the on-device download keeps failing (it's about 50 MB over the Pager's 2.4 GHz client
  Wi-Fi), install from USB instead. Copy the signed `.bin` to `/tmp` (it's RAM, so check
  `free` first) and run `INSTALL_FIRMWARE /tmp/<file>.bin` from SSH. It checks Hak5's signature
  before flashing. Run it detached (`setsid … &`), because sysupgrade closes the session. The
  first boot after the update takes several minutes, while it copies the new system image to the
  eMMC.
- To restore your theme after updating:
  `uci set system.@pager[0].theme_name=<name>`,
  `uci set system.@pager[0].theme_path=/root/themes/<name>`, `uci commit system`, then
  `/etc/init.d/pineapplepager restart`.

## Payloads: launch, stop and PATH — *verified*
Tested by launching payloads from the menu. Each one started a `setsid` worker and a plain
`( … ) &` child:

| | `setsid` worker | plain `&` child |
|---|---|---|
| Payload ends by itself | survives | survives |
| Stopped from the UI ("Stop payload execution?") | **survives** | **killed** |

- The UI starts each payload as the **leader of its own process group**, and stopping kills the
  whole group. A toggleable background watcher (`setsid` plus a pidfile, run again to turn it
  off) works as before. Anything you start with a plain `&` dies if the user stops the payload.
  pineapd treats the alert payloads it starts the same way.
- **`PATH` is now**
  `/usr/local/bin:/usr/local/sbin:/usr/bin:/usr/sbin:/bin:/sbin:.:/mmc/bin:/mmc/sbin:/mmc/usr/bin:/mmc/usr/sbin`.
  Tools kept in `/mmc/bin` work without links. **`.` is on `PATH`**, so don't put a file named
  like a system command in your payload folder.
- Still missing: `pkill`, `nohup`. Use `setsid` and a pidfile.

## Storage: root on the eMMC — *verified*
- `/` is an overlay whose writable layer is on the eMMC; a copy of the system image is kept in
  `/mmc/.rom`. `/mmc` is still mounted, and `/root` is still a link to `/mmc/root`.
- Login shells add `/mmc/bin` and friends to `PATH` (`/etc/profile.d/emmc.sh`).
- If the eMMC is too full to finish booting after an update, the Pager clears old system copies
  and caches. If that's still not enough, it serves a recovery page over USB-C at port 1471.

## SSH: dropbear — *verified*
- The OpenSSH server was replaced by dropbear. Keys and `authorized_keys` carried over. The host
  keys are stored on the eMMC, so later updates keep them. `scp` and `sftp-server` still ship,
  so `scp` and `sftp` from a computer still work.

## Audio: a real sound card — *verified*
- The buzzer is ALSA card 0 (`pager-pcm`, device `pcmC0D0p`).
- `pwmplay file.mp3` plays an mp3 through it, resampled to 16 kHz and shaped for the buzzer. Speech
  is clear. A 2.7 s clip used 0.1 s of CPU with no dropouts. Options include `-g` (gain, %),
  `-t` (seconds) and `-r` (rate).
- The faint idle whine from the buzzer is gone.

## Commands
- **New:** `PINEAPPLE_KICK_CLIENT <mac> [block]` disconnects a client from the Pager's own APs.
  `block` also moves it to the deny list.
- **New:** `PINEAPPLE_PINEAPD_STOP` / `PINEAPPLE_PINEAPD_RESPAWN` are developer commands that keep
  PineAP stopped, for testing.
- **New helpers** in `/lib/hak5/commands.sh`: `HAK5_API_WAIT_NETWORK [seconds]` (waits until a
  network change has finished applying) and `VALIDATE_AP_CERT`.
- **`HAK5_API_GET/POST/PUT`** now accept any 2xx status as success. They print "API server not
  reachable" or "API request failed: HTTP n", and send the request body on stdin (so secrets no
  longer show in `ps`).
- **Fixed:** `PINEAPPLE_SET_BANDS` now does what it says. `WIFI_WAIT` waits for a real (not
  link-local) IP. `PAYLOAD_DEL_CONFIG` saves. Dialogs no longer crash on non-UTF-8 text such as
  odd SSIDs. `SYSTEM_LOG_WARNING`/`_ERROR` use the right levels.
- **Security:** `PINEAP_SSID_MATCH` callbacks now receive SSIDs as arguments rather than through
  `eval`, so an SSID heard over the air can no longer run commands. If you wrote your own SSID
  handling, quote it.

## Local API — *partly verified*
New routes, under `curl --unix-socket /tmp/api.sock http://localhost/api/…`:
- `recon/captures` (verified): handshakes, Evil WPA and enterprise captures.
- `settings/wifi/enterprise_ap` (verified), with `/certificate`, `/certificate/ca`,
  `/certificate/upload`, `/profiles` (verified) and `/profiles/{name}/apply`.
- `network/change_applying` (verified): `{"change_applying":false}`.
- `status` (verified) now reports `booted`, `version`, `channel`, `uptime` and the upgrade state.
- `clients/kick`, `pineap/stop`, `pineap/respawn`, `pineap/log/handshakes/start|stop`.
- Removed: `debug/memory`.

## Recon database and pineapd — *verified*
- `/root/recon/recon.db` now uses SQLite **WAL** mode, with `recon.db-wal` and `recon.db-shm` beside
  it. Query it live with `sqlite3`, or copy all three files. Copying only `.db` loses recent rows.
- pineapd runs under a memory limit (`--memlimit 100`, in MiB). When it gets close, it saves the
  scan and starts a new one, so very busy places no longer exhaust memory.
- **Don't run `pineapd --help`.** There is no help: it starts a second pineapd, which takes over
  the control socket and knocks the real one offline. To recover, kill the extra process and
  run `/etc/init.d/pineapd restart`. To see pineapd's options, read `ps w` or
  `/etc/init.d/pineapd`.
- WiGLE and pcap file names keep their format. `WIGLE_STOP` deletes a log that never received a
  row.
- To find pineapd's PID, use `pgrep pineapd` or `pidof pineapd`. **`pgrep -x pineapd` returns
  nothing**, even while it runs.

## Time zone — *verified*
On 2.0 a zone such as `UTC+6` meant "6 hours behind UTC, labelled UTC", so `date` already
printed local time while calling it UTC. 2.1 rewrites it as `<-06>+6`: the same clock, now with
an honest label. (PineAP's own WiGLE log names stay in UTC, `+0000`; the Bluetooth `wigle-bt-*`
logs use local time.) **If a payload needs real
UTC (WiGLE CSV timestamps, for example), use `date -u` or `TZ=UTC0`.** This was true on 2.0 as
well.

## Themes
Nothing to change: the framework (0.9), the template variables and the theme functions are the
same as 2.0.0. The stock theme is identical. The faster display can make animations tuned on 2.0
look a little quicker. Remember to switch back to your theme after updating (see above).
